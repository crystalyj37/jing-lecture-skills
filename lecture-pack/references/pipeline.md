# 一份内容，三份文件

## 三种读者，三种写法

| | 详细材料 handout | 演示 slides | 讲稿 script |
|---|---|---|---|
| 谁读 | 听众、学生，会后独自读 | 台下的人，抬头看 3 秒 | 只有你 |
| 在哪读 | 手机、打印、PDF | 投影，3 米外 | 讲台上，扫一眼 |
| 长什么样 | 完整段落 + 表 + 出处 | 短句 + 一个结构 | 口播句 + 时间 + 提示 |
| 语气 | 书面、可独立成立 | 判断句、不解释 | 口语、有停顿 |
| 长度 | 一场 90 分钟 ≈ 1.5–3 万字 | 一屏 ≤ 80 字 | 按 240 字/分钟配 |
| 允许省略 | 什么都不许省 | 除了结论都省 | 除了要说出口的都省 |

**一张表说明这不是「排版三遍」**：同一句「AI 不是一个模型」，

- 材料里：从「为什么这个区分重要」写到「三类模型各自的成本结构」，带出处，读者没听你讲也能懂
- 屏上：`模型不止一种：看它吃什么、吐什么` + 一张六行表
- 讲稿：「大家说的豆包真聪明，其实是六个模型叠在一起干活。我先停一下——你们觉得，画图和聊天，是同一个模型吗？」

三句话内容一致，但**句子不能互相搬**。搬过去就会：屏上字太多、材料像提纲、讲稿像念稿。

## 铁律

1. **顺序只在一处改**——内容清单。三份的顺序必须一致。
2. **数字只在清单里写一次**——三份引用同一处。改数字先改清单，再 `crosscheck.py`。
3. **讲稿里的每一句都要能说出口**。写「本单元旨在阐明……」的，是材料跑错地方了。
4. **屏上不放论证**。放结论和结构；论证归材料，讲的时候用嘴补。
5. **材料不写「刚才讲过」**。读者可能没在场。任何依赖现场的指代都要删掉。
6. **三份都不许有"待补"。** 有一处没定，就先别定稿——半成品流到听众手里收不回来。

## 顺序

```
议题 / 受众 / 时长
      ↓
content-map.md         ← 唯一事实源，先定 25–40 个单元
      ↓
  ┌───┴────┬─────────┐
  ↓        ↓         ↓
script   handout   deck.deck.md
  ↓        ↓         ↓
.md      .md/.html  lecture-slides → .html
  └───┬────┴─────────┘
      ↓
crosscheck.py          ← 对账：单元、顺序、数字、时长
```

**先写讲稿，再写材料，最后做 slides。** 理由：讲稿逼你把话说完整，说完整了才知道哪些能砍；
先做 slides 会不自觉地把「话」压成「词」，回头写讲稿时已经想不起原来要说什么。

熟练之后可以并行，但第一版别跳。

## 时长怎么配

中文口播 **240 字/分钟**（正式场合偏慢，讲得快的按 280）。

| 时长 | 讲稿字数 | 单元数 | 屏数 |
|---|---|---|---|
| 20 分钟 | 4.5–5.5 千 | 8–12 | 12–18 |
| 45 分钟 | 1.0–1.2 万 | 15–20 | 25–32 |
| 90 分钟 | 2.0–2.4 万 | 25–40 | 45–55 |

清单里各单元 `时长` 之和，应该留 5–8% 余量给现场问答和意外的卡顿。
**加总刚好等于总时长，实际一定超。**

## 什么时候不必三份都做

| 场合 | 做什么 |
|---|---|
| 内部周会、5 分钟同步 | 只做 slides |
| 录播课、线上讲座 | 讲稿 + slides（讲稿即字幕底稿） |
| 投稿、评审、存档 | 只做 handout |
| 对外分享、要留资料 | **三份都要**，材料是唯一能带走的东西 |

判断标准：**听众散场后，手里还剩什么。** 什么都没有，就必须有材料。

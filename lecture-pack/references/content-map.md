# 内容清单 `content-map.md`

三份产物共用的唯一事实源。**先写它，再写别的。** 跳过这一步直接写 slides，必然要回头改三遍。

## 为什么要它

一份讲稿写成三份文件，最大的风险不是写得慢，是**改了一处、三份不同步**。
数字在 slides 上是 460，在材料里还是 400；讲稿删了一段，屏上还留着。
内容清单的作用是把「事实、例子、数字、收口句」抽出来放一处，三份都从这里取。

## 单元

一个单元 = 讲台上能独立讲完的一个意思。**一屏最多承载一个单元，一个单元可以占一两屏。**

```markdown
### U2.0 · 先分一刀：AI 不是一个模型
- 时长：2′
- 断言：豆包不是一个模型，是六类模型叠着用。
- 证据：
  | 类别 | 吃什么 → 吐什么 | 豆包里的哪一环 |
  | --- | --- | --- |
  | 文本模型（LLM） | 文字 → 文字 | 打字提问，返回文字 |
  | 语音识别（ASR） | 声音 → 文字 | 按住说话，先转成文字 |
- 例子：按「打电话」走的是 S2S，中间不产生文字。
- 误区：拿聊天模型的表现，评价「这个 AI 好不好用」。
- 收口：先问这是哪一类模型，再问它强不强。
- 屏：n1, n2
- 不上台：型号全名、单价、embedding（留材料里）
- 来源：六类划分依 OpenRouter 目录与各产品文档整理
```

## 字段

| 字段 | 必填 | 写什么 | 落到哪 |
|---|---|---|---|
| 标题 | ✓ | `U<节>.<序> · <一句话断言>`，断言不是主题词 | 三份都用 |
| 时长 | ✓ | 分钟数，写 `2′` 或 `2.5′` | 讲稿配速 |
| 断言 | ✓ | 一句话，可直接当屏标题 | slides 标题、材料首句 |
| 证据 | 有数据就填 | 表格 / 数字 / 引用原文 | 三份共用，**不许各写一遍** |
| 例子 | ✓ | 具体到能被复述的场景 | 讲稿必用，材料展开 |
| 误区 | | 听众会怎么想错 | 讲稿用来设问，材料用来纠偏 |
| 收口 | ✓ | 讲完这一单元的那一句 | 讲稿原话，slides 可作 `.strip` |
| 屏 | 有 slides 就填 | deck 里的 `screen id`，逗号分隔 | crosscheck 对账 |
| 不上台 | | 只写进材料、不占讲台时间的内容 | 材料只 |
| 来源 | 有数字就填 | 出处，可核查 | 材料脚注 |

## 写法上的几条硬规矩

1. **断言必须是判断句。**「模型分几类」是主题，「AI 不是一个模型，是六类叠着用」才是断言。slides 和讲稿都靠断言走。
2. **证据只写一份。** 表格在清单里写全，slides 里复制同一张表，材料里也是同一张。三处数字不一致，是这类工作最常见的翻车。
3. **`不上台` 不是垃圾桶。** 它是有意的取舍记录：为什么这段不占讲台时间。写清楚理由，下次复用才知道边界。
4. **一个单元只有一个收口句。** 想收两次，就是两个单元。
5. **单元顺序 = 讲台顺序 = 材料顺序 = 屏序。** 三份的顺序不允许自己调。要调，改清单。

## 单元切分

切到多细？按「讲台上会不会停一下」切：

- 讲 90 秒、要停一下让人消化 → 一个单元
- 连着念完不停 → 合成一个
- 一个单元超过 4 分钟 → 拆开（听众的注意力撑不住）

一场 90 分钟的分享，通常 **25–40 个单元**。少于 20 个，说明每段太长；多于 50 个，说明切碎了。

## 清单头部

```markdown
# 内容清单 · 示例分享（90 分钟）

- 受众：高校各学科教师，无 AI 基础
- 时长：90 分钟（含 10 分钟现场动手）
- 一句话目的：让老师带走一张能用的地图，和一个明天就能做的动作
- 产物：handout（详细材料）· deck（slides）· script（讲稿）
- 状态：初稿 / 已对稿 / 已定稿
```
